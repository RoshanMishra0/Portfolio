What Is Activation Steering?

Activation steering (also called representation engineering or concept steering) is a mechanistic interpretability technique that controls model behaviour by modifying internal activations at runtime. No prompt changes, no retraining.

The key insight: transformer hidden states encode semantic directions. If you can identify the direction in activation space that corresponds to a concept (e.g. "formality"), you can add or subtract that direction during a forward pass to push the model's output toward or away from that concept.

What it is NOT

  • → Not prompt engineering (no instruction change)
  • → Not fine-tuning (no gradient updates)
  • → Not RLHF or preference data
  • → Not system prompt manipulation

What it IS

  • → Direct intervention in the forward pass
  • → Adding a concept vector to a layer's hidden state
  • → Weights stay frozen — only activations change
  • → Works at inference time on any input

Model Setup: 4-bit Quantization

Mistral 7B is loaded in 4-bit NF4 quantization using bitsandbytes. This keeps the model runnable on consumer hardware while preserving enough representational fidelity for the hidden-state geometry to remain meaningful, which is crucial for activation steering to work.

from transformers import AutoModelForCausalLM, BitsAndBytesConfig import torch bnb_config = BitsAndBytesConfig( load_in_4bit=True, bnb_4bit_compute_dtype=torch.float16, bnb_4bit_use_double_quant=True, bnb_4bit_quant_type="nf4", # Normal Float 4 — better distribution than uniform 4-bit ) model = AutoModelForCausalLM.from_pretrained( "mistralai/Mistral-7B-v0.1", quantization_config=bnb_config, device_map="auto", ) model.eval() # inference only — no gradient tracking needed

Computing Steering Vectors

A steering vector is computed as the difference between mean hidden-state activations for two contrastive sets of prompts: one representing the target concept, one representing the opposite.

For the formality experiment: formal prompts ("provide a rigorous, mathematically grounded explanation...") versus casual prompts ("explain like I'm 5"). The mean activation difference at the last token position gives a direction in hidden-state space that encodes the formality concept.

Formal prompts → forward pass → last-token hidden state → mean_formal Casual prompts → forward pass → last-token hidden state → mean_casual steering_vector = (mean_formal - mean_casual) / ||mean_formal - mean_casual|| shape: (1, 1, hidden_dim) — broadcast-safe for hook injection
def get_hidden(prompt: str, layer_id: int) -> torch.Tensor: cache = {} def hook(module, input, output): h = output[0] if isinstance(output, tuple) else output cache["h"] = h.detach() inputs = build_inputs(prompt) handle = model.model.layers[layer_id].register_forward_hook(hook) with torch.no_grad(): model(inputs) # forward pass only, no generation handle.remove() return cache["h"] # shape: (1, seq_len, hidden_dim) def compute_steering_vector(layer_id, formal_prompts, casual_prompts): formal_vecs = [last_token(get_hidden(p, layer_id)) for p in formal_prompts] casual_vecs = [last_token(get_hidden(p, layer_id)) for p in casual_prompts] vec = (torch.stack(formal_vecs).mean(0) - torch.stack(casual_vecs).mean(0)).unsqueeze(1) return vec / (vec.norm(dim=-1, keepdim=True) + 1e-6) # unit-normalised

Injecting the Vector via Forward Hook

At inference time, a PyTorch forward hook intercepts the output of a specific transformer layer and adds alpha × steering_vector to the hidden state before it flows into the next layer. Alpha controls the steering strength: too low and the effect is imperceptible, too high and it degrades coherence.

def make_steering_hook(steering_vector, alpha: float): def hook(module, input, output): if isinstance(output, tuple): steered = output[0] + alpha * steering_vector return (steered,) + output[1:] # preserve past_key_values etc. return output + alpha * steering_vector return hook # Register hook at 75% layer depth, alpha = 4.0 layer_id = math.floor(len(model.model.layers) * 0.75) handle = model.model.layers[layer_id].register_forward_hook( make_steering_hook(steering_vector, alpha=4.0) ) output = generate("Explain gravity in simple terms.") handle.remove() # always remove — hook persists across calls otherwise
Why remove the hook after generation? PyTorch forward hooks persist on the module until explicitly removed. If you don't call handle.remove(), every subsequent forward pass through that layer (including internal KV cache updates) will apply the steering vector, producing corrupted outputs.

Experiments: Layer Depth vs Alpha

Two experiments test different injection points and steering strengths on the same test prompt: "Explain gravity in simple terms."

Experiment Layer Depth Alpha (α) Effect
Baseline — 0 Casual, accessible explanation
Experiment 1 75% depth 4.0 Strong shift to formal/technical register
Experiment 2 50% depth 0.5 Subtle formalisation, coherence preserved

Deeper layers (75%) carry more semantic content. They're closer to the output distribution and respond more strongly to the steering vector. Earlier layers (50%) carry more syntactic/structural information; the same vector has a subtler effect there. This matches the mechanistic interpretability literature on layer specialisation in transformers.

Key finding: At α = 4.0 on layer 75%, the model shifts from "things fall because gravity pulls them" to full physics register, discussing gravitational fields, Newton's inverse-square law, and geodesics, without any change to the input prompt or model weights.

Why This Matters for AI Engineering

  • No retraining cost. Fine-tuning Mistral 7B for tone control would require GPU hours, labelled data, and a PEFT setup. Activation steering achieves comparable tone shifts at inference time with zero weight updates.
  • Composable and reversible. Hooks can be stacked, mixed, or removed on any call. You can steer one request toward formal tone and the next toward casual, from the same loaded model, by simply registering or removing hooks.
  • Reveals model internals. The fact that a linear direction in hidden-state space reliably encodes "formality" is not obvious. It's evidence that transformers learn structured semantic geometry, not just statistical token correlations.
  • Practical path to safe deployment. Activation steering is being actively researched for harmlessness interventions — steering away from harmful concept directions without RLHF. This project is a direct implementation of those ideas on a real 7B model.

What I'd Do Next

  • Quantitative evaluation. Currently the output difference is qualitative. Adding automated eval (e.g. a classifier scoring formality on a held-out set) would make the alpha-vs-layer tradeoffs measurable.
  • Multi-concept steering. Composing two steering vectors simultaneously (e.g. formal + concise) to test whether the directions are additive or interfere with each other.
  • Negative steering. Subtracting the formality vector (alpha < 0) to push the model toward casual register from a neutral prompt, testing directional symmetry.
  • Layer sweep. Running the same steering vector across all 32 layers independently to build a layer-wise sensitivity map, identifying which layers have the cleanest semantic geometry for this concept.
