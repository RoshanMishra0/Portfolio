GitHub →

Problem Statement

Stress detection from self-reporting is unreliable. People either don't notice early stress signals or don't report them accurately. Wearable devices continuously collect physiological signals that are better stress predictors than subjective reports, but raw sensor data is meaningless without a classification layer.

The additional challenge: stress detection alone isn't useful. A system that detects stress but can't respond to it is just a diagnostic. This project builds the full loop: detection, classification, and a personalised LLM-powered intervention generated for each user's state.

System Architecture

Wearable Sensors → HR, HRV, EDA, Respiration │ ▼ Feature Extraction (preprocess_wesad.py) ├── Statistical features: mean, std, min, max per signal ├── HRV time-domain features: RMSSD, SDNN └── Output: stress_features.csv │ ▼ Random Forest Classifier (stress_model.pkl) ├── Trained on WESAD S2–S6 subset ├── Target: Relaxed vs Stressed └── Output: class + confidence score │ ▼ FastAPI Backend /predict ├── Receives sensor readings ├── Runs classifier ├── Calls Phi-3 Mini → personalised nudge └── Stores result in SQLite (stress_app.db) │ ▼ React Frontend ├── Mobile-style input UI ├── Prediction + confidence display ├── Calming nudge display ├── Feedback submission → /feedback └── User dashboard → /dashboard/{user_id} Phi-3 Mini served via HuggingFace Inference API (no local GPU needed)

Dataset: WESAD

WESAD (Wearable Stress and Affect Detection) is a multimodal dataset collected using chest- and wrist-worn sensors. This project uses subjects S2–S6 and focuses on the binary classification task: Relaxed vs Stressed.

Input signals used

  • → HR: Heart Rate (BPM)
  • → HRV: Heart Rate Variability
  • → EDA: Electrodermal Activity (skin conductance)
  • → Respiration rate

Feature engineering

  • → Sliding window aggregations (mean, std, min, max)
  • → HRV time-domain: RMSSD, SDNN
  • → EDA tonic + phasic decomposition
  • → Output: tabular feature matrix → stress_features.csv

LLM Nudge Layer: Phi-3 Mini

The classifier output (class + confidence) is fed into a structured prompt for Phi-3 Mini via the HuggingFace Inference API. The LLM generates a personalised calming intervention (breathing guidance, grounding technique, or cognitive reframe) tailored to the predicted stress level.

Design decision: Phi-3 Mini was chosen over larger models because the nudge task is narrow and well-defined. A small, fast model on a public inference API keeps latency low and removes the need for local GPU resources, which matters for a real-time wearable application where response time is important.

The nudge prompt is structured to constrain output length and format. The LLM is instructed to return a 2-3 sentence intervention, not a long explanation. This is a practical application of the same schema-constraint principle from the Fleet Classifier project: smaller, more constrained outputs are more useful in a real UI than long freeform text.

Feedback Loop & Dashboard

After receiving a nudge, the user submits feedback on whether it was helpful. This is stored in SQLite and surfaced in a per-user dashboard showing:

  • Stress prediction history over time
  • Nudge effectiveness by type
  • Pattern detection (time-of-day, trigger signals)

The API exposes GET /dashboard/{user_id} which returns aggregated analytics. The frontend renders this as a user-specific trend view: not just a raw prediction, but a longitudinal view of the user's stress patterns.

What I'd Do Differently

  • Replace Random Forest with a temporal model. Stress is a temporal signal. The sequence matters, not just the feature snapshot. An LSTM or Transformer on the raw time series would likely outperform the feature-engineering + RF approach.
  • On-device inference. For a real wearable product, running the classifier on-device rather than in a backend API would eliminate network latency and privacy concerns around transmitting raw biometric data.
  • Personalised model adaptation. The current model is trained on the WESAD population. Individual physiological baselines vary significantly. Online learning from per-user feedback would let the classifier adapt to each user's specific stress signatures over time.
